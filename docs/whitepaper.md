# ScribeFlow 技术白皮书

> 面向非技术读者｜文档状态：已验证事实｜最后验证：2026-08-01｜项目版本：0.1.0

## 1. 软件解决什么问题

本软件把扫描版 PDF 变成可搜索、可编辑、可按章节使用的 Markdown 文档，同时尽量保留标题、正文、表格和图片。它适合整理教材、档案和扫描资料，但不是法律意义上的原文认证工具。

## 2. 一次转换发生什么

程序先读取 PDF 页数，然后由本机 MinerU 模型识别文字和版面。识别结果会被拆成内容块，再删除明确的页眉、页脚、页码和广告。之后生成完整文档、章节文件、图片资源和审计记录。

如果开启 AI，AI 只判断哪些块可能是噪声、哪些相邻块应合并、标题层级是否需要调整。它不能重写正文，因此每次清洗都能追溯到原始内容块。

## 3. 模型和网络

OCR 主要在本机运行，模型可能从 ModelScope、HuggingFace 或本地源获取。AI 清洗是可选的，使用 OpenAI 兼容接口；开启后，内容块会发送到配置的服务。API 密钥保存在 macOS 钥匙串，不写入日志、事件或输出清单。

## 4. 如何判断结果是否可信

程序会输出 `manifest.json`、`cleaning_audit.json` 和完整日志，记录输入、参数、模型、章节和产物。关键材料仍应人工抽查，尤其是低清扫描、双栏排版、复杂表格、公式和跨页内容。

## 5. 结果和隐私边界

输出目录包含完整 Markdown、章节 Markdown、图片、可选的 MinerU 原始结果、清洗审计和日志。使用 AI 时，用户应确认外部接口的数据处理政策；关闭 AI 可只使用本地 OCR 流程。

## 6. 已知限制和故障处理

厚文档可能消耗较多内存，程序会自动降低批处理页数。模型首次下载可能较慢。遇到超时、502 或 OCR 失败时，程序会保留失败现场，便于重试和定位；必要时可拆分 PDF。

## 7. 长期维护

项目把架构、流程、模型、配置、依赖、性能和已知问题放在同一文档中心。代码或配置改变后，文档检查会发现缺失的参数、事件或版本记录；白皮书由 Markdown 自动生成，避免 PDF 与源文档分叉。
